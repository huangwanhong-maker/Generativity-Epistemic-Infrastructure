Release configuration, build and full regression gate:

```powershell
& $cmake -S GR-OS -B GR-OS/build -G 'Visual Studio 17 2022' -A x64 `
  -DGR_BUILD_TESTS=ON -DGR_BUILD_BINDINGS=ON -DGR_BUILD_DATA=ON `
```

fixes (qualified floating host, additional numerical fixtures, pinned package
limits, stricter dependency/error probes and expanded example), the final gate
passed 38/38 in 106.64 seconds. See `ctest-v0.6-release-initial.txt`,
`ctest-v0.6-release-final.txt`, and `ctest-v0.6-release-detail.txt`. The associated
configure/build logs use the same version and `release-final` suffix. Logs were
normalized to UTF-8 after the process closed; their content was not filtered.

The 17 Python data cases used Python 3.12.10 with actual NumPy available, including
full-width uint64 and complex128 imports and readonly exports after native handle
closure. The 16 legacy Python, 17 runtime and 9 buffer cases also passed. Native
counts include language 83, numeric 89, standard 42, sparse 108, relational 61 and
access 58. These counts describe bounded fixtures, not universal equivalence.

AddressSanitizer configuration and selected gate:

```powershell
& $cmake -S GR-OS -B GR-OS/build-asan -G 'Visual Studio 17 2022' -A x64 `
  -DGR_BUILD_TESTS=ON -DGR_BUILD_BINDINGS=ON -DGR_BUILD_DATA=ON `
  -DGR_BUILD_BENCHMARKS=OFF -DGR_TEST_TIMEOUT_MULTIPLIER=8 "-DPython3_EXECUTABLE=$python" `
  '-DCMAKE_CXX_FLAGS=/fsanitize=address /Zi /EHsc' '-DCMAKE_C_FLAGS=/fsanitize=address /Zi' `
  '-DCMAKE_EXE_LINKER_FLAGS=/INCREMENTAL:NO /DEBUG' `
  '-DCMAKE_SHARED_LINKER_FLAGS=/INCREMENTAL:NO /DEBUG' `
  '-DCMAKE_MODULE_LINKER_FLAGS=/INCREMENTAL:NO /DEBUG'
& $cmake --build GR-OS/build-asan --config Release --parallel 4
& $ctest --test-dir GR-OS/build-asan -C Release --output-on-failure -j 1 -E '^python_binding$'
```

Only the unchanged legacy `python_binding` CTest is excluded from this sanitizer
gate, following the prior validated scope: its 10,000-record capacity fixture had
extreme ASan allocation overhead. The complete unchanged test passed Release.
All native C/C++ targets, including SQLite, use the listed sanitizer flags; Python
and NumPy interpreters themselves are not instrumented. The installed harnesses
inherit compiler/linker instrumentation and stage the installed ASan runtime DLL
only within the build-local test directories. No global runtime installation or
environment alteration is required. There is no ThreadSanitizer, arbitrary-host
floating conformance, power-loss or sandbox claim.

The initial ASan run completed **36/37 in 357.95 seconds**. All native and Python
behavioral tests passed, including both actual NumPy data tests and the NumPy
example, and the independent package passed. `installed_sdk` failed before its C
consumer could start with Windows status `3221225781`: the harness staged the
ASan runtime only later, before ctypes, and the global Python environment did not
incidentally supply that DLL to earlier native executables. The failure is retained
in `ctest-v0.6-asan.txt` and `ctest-v0.6-asan-initial-detail.txt`.

The test-only correction stages the installed toolchain runtime beside the relocated
DLL and native consumer executables before invocation. It also selects the existing
build-local packaging-tool venv consistently across build configurations. No
production code changed. An independent read-only review checked the scope and
ordering. The affected gate was rerun, with both passing:
