# v0.6 build, SDK and measurement reproduction

Class: local engineering evidence. Date: 2026-10-15 JST. Run from GR-OS in
PowerShell. Use fresh log destinations when repeating these commands. Native
dependencies are pinned in-tree; existing build-local packaging tools are used
offline. No system-wide installation or network download is part of verification.

```powershell
$taskCmake = 'C:/Program Files/Microsoft Visual Studio/2022/Community/Common7/IDE/CommonExtensions/Microsoft/CMake/CMake/bin/cmake.exe'
$taskCtest = 'C:/Program Files/Microsoft Visual Studio/2022/Community/Common7/IDE/CommonExtensions/Microsoft/CMake/CMake/bin/ctest.exe'
$taskPython = 'C:/Users/Micro/AppData/Local/Programs/Python/Python312/python.exe'
& $taskCmake -S . -B build -G 'Visual Studio 17 2022' -A x64 -DGR_BUILD_DATA=ON -DGR_BUILD_BENCHMARKS=ON -DGR_REQUIRE_PYTHON_TESTS=ON -DGR_TEST_TIMEOUT_MULTIPLIER=1 "-DPython3_EXECUTABLE=$taskPython"
& $taskCmake --build build --config Release --parallel 4
& $taskCtest --test-dir build -C Release --output-on-failure
```

`installed_sdk` installs and relocates the GR SDK, builds external C/C++ consumers,
and builds/installs the Python wheel offline using `build/sdk-venv`. The selected
Release interpreter supplies actual NumPy. `independent_package` separately copies
the package source, rejects missing/wrong dependencies, builds against a relocated
installed SDK, installs/relocates the package and tests external C++ and its wheel.
Its per-run `commands.json` records exact subprocesses and diagnostics;
`artifacts.json` records package manifest and native/wheel hashes. Neither harness
uses a package `add_subdirectory` in the core build.

& $taskCmake --build build-asan --config Release --parallel 4

The multiplier changes only outer watchdogs. The selected ASan suite excludes the
unchanged expensive legacy Python capacity test; it remains included in full
Release. Numerical, cache/Function, new Python/NumPy, ownership, transaction and
independent-package paths are selected. The package harness propagates sanitizer
flags and stages the runtime locally. Actual outcomes/skips appear in
[verification](../verification.md); configuration alone is not a pass.

Default-plan captures use the explicit fixture in
[`capture_default_plan.py`](../../tools/capture_default_plan.py), once with the
preserved v0.5 facade/DLL and once with v0.6. This new matched fixture is recorded;
it does not claim to reconstruct the undocumented payload of older captures.

After builds/tests end, run [`measure_v06.py`](../../tools/measure_v06.py) with the
accepted Release package run directory and a fresh label, as described in the
[benchmark protocol](../../benchmarks/README.md). It records serial commands and
raw captures. Initial measurements are retained separately. No timing gate is
used; the analysis reports regressions and host variability as well as gains.
