# v0.6 assessment and implementation plan

Class: implementation assessment and plan. Maturity: experimental. Date: 2026-10-15.
The user authorized assessment followed by a bounded substantive v0.6 increment,
then architectural review. This supersedes the v0.5 stop point for this scope only.

## Evidence and diagnosis before edits

The v0.5 implementation, ADR-0005, public native/SDK contracts, conformance and
installed consumers, verification report and raw benchmark analysis were reviewed.
All 247 recorded source/artifact hashes matched before preservation. The complete
unchanged Release suite passed 35/35 in 67.87 s. A 189-file source/document archive,
installed SDK, Python facade, benchmark executables and evidence are retained in
`build/baselines/v0.5/` and `docs/validation/v0.5-pre-v0.6/`.

The six-node 262,144-row pipeline took about 1,115 ms prepared serially in v0.5;
qualified transforms over 256 relations took about 928 ms. These are phase
measurements, not sampled CPU attribution. Source inspection identifies repeated
immutable input/output representation validation, repeated named-buffer lookup and
per-element extent/index checks, and qualified-source parsing/reconstruction/copying.
Instrumentation and matched measurements will test these explanations.

These are primarily implementation costs. The separation of structural logical
types, representations, generic operators, concrete runtime plans and physical
providers remains useful. Replacing it with a universal tensor abstraction, another
scheduler or a bytecode VM would not address the measured work. The distribution
gap is architectural: the in-tree CSR example has not demonstrated an independently
built installed package. Numerical storage alone also does not supply an arithmetic
contract for scientific consumers.

## Selected bounded direction

1. Preserve old contracts and results while adding bounded validation reuse tied to
   the actual immutable payload owner, exact logical specification and sealed
   library. Weak ownership tokens prevent address reuse without retaining payloads;
   never trust a caller digest,
   tag or mutable metadata as a certificate. New owners and failures remain checked.
   Budgets and observability make cache costs and eviction explicit.
2. Add owning checked batch access for contiguous/strided host views. Validate
   geometry once, retain storage lifetime, preserve endian/alignment safety and
   scalar fallbacks, and keep cancellation and checked arithmetic in hot loops.
3. Retain immutable parsed qualified source/view state inside a bounded module
   context. Preserve exact source revisions, occurrence keys, temporal status and
   losses. Imported bytes still undergo complete derivation validation. Avoid a new
   kernel carrier or a lossy flattened source format for this optimization.
4. Add a small optional numerical extension with explicit unsigned and finite
   floating/complex domain rules, conversion/error policy and independently checked
   conformance. Fixed traversal and a qualified arithmetic environment must not be
   confused with exact real-number mathematics or universal CPU/GPU equivalence.
5. Make immutable named expression graphs usable as function-like composition
   objects, while retaining explicit input binding, shared dependencies, pure
   computation and existing runtime plans. Reuse specialization where its exact
   immutable inputs justify it; no automatic algebraic rewrite or implicit cast.
6. Demonstrate a separately configured, installed and relocated source package
   against the installed SDK. Exact dependency/package identity and clear native
   lifecycle are needed now; a stable cross-compiler binary plugin ABI, package
   solver and secure native sandbox are deferred. Exercise C++ and practical Python
   consumption and a small composed higher-level consumer.

## Alternatives and trade-offs

Content-addressed global validation caches were rejected: they need additional
custody, executable-validator identity, collision and retention rules. Bounded
owner-based reuse is narrower and inspectable. It can miss equivalent copies and
retains limited cache metadata; the relational parsed-state cache separately
retains bounded decoded state. Counters and clear controls expose these costs.

Opaque typed payloads could avoid all qualified JSON rebuilding, but would add a
new cross-language/lifetime contract immediately. Retained parsed state preserves
the existing portable wire format first. Larger-scale shared source references
remain a future option with independent availability/custody requirements.

Full IR fusion, persistent streaming, approximate parallel reductions, GPU/JIT and
automatic semver resolution remain deferred. Explicit coarse providers and safe
batch access provide a smaller step; future rewrites require numerical and null
equivalence rules. Exact version pins are deliberately stricter than compatibility
claims inferred from version spelling.

## Verification and acceptance

Run meaningful adversarial tests for reuse invalidation, different libraries and
owners, malformed values, concurrency/eviction, striding, nullable arithmetic,
overflow/underflow/nonfinite values, rounding policy and independent provider
agreement. Exercise extension installation outside the core build, missing/wrong
dependencies, relocated C++/Python consumers and retained lifetimes.

Preserve and rerun unchanged v0.5 benchmark executables against equivalent v0.6
workloads/settings. Add small/medium/large and scalar/batch/cold/warm measurements
with instrumentation counters/timing and explicit memory scope. Report regressions
and host variability. Run full Release and useful sanitizer coverage, document
skips, and retain raw logs, hashes and commands. Keep transaction/history regression
tests unchanged unless a demonstrated defect requires a separately explained fix.

All work stays in GR-OS. No generalized/academic application migration, domain
research methodology, broad Layer 2 ecosystem or programme-source edits are included.
The final review will distinguish readiness for selected independent modules from
production-scale, heterogeneous-device or platform-wide qualification.
