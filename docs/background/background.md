# Background

## 1. Purpose

This document records the conceptual background motivating a standards program for generativity records and their presentation.

It is informative, not normative.

## 2. Problem setting

Conventional archival, provenance, and publication practices often preserve outputs more reliably than the processes through which those outputs became possible.

A finished paper, policy, institution, artwork, dataset, or decision may survive while the following become difficult to reconstruct:

- enabling conditions;
- contingent encounters;
- changes in interpretation;
- unrealized branches;
- transformations of relations;
- losses of possible continuations;
- later reinterpretations;
- the role of infrastructures, tools, communities, and non-human systems.

The program therefore investigates standards for recording and presenting generativity as trajectory rather than only as output.

## 3. Existing metamodel background

The current theoretical background uses a deliberately weak highest-level formalism built around:

- a carrier of states;
- mechanisms acting on states;
- an equivalence relation or observational indistinguishability structure;
- a notion of action/composition.

At that level, four central formal dimensions have been emphasized:

- Change
- Structure
- Constraint
- Difference

The protocol and standards program should remain compatible with that abstract layer while avoiding the assumption that the operational recording vocabulary is itself metaphysically fundamental.

## 4. Candidate operational record ontology

The current candidate operational ontology contains six classes:

1. Entity
2. State
3. Event
4. Process
5. Relation
6. Property

These classes are intended as standardized forms for recording and exchange.

They remain provisional until GR-100 defines them.

## 5. Important conceptual distinction

The program currently distinguishes:

\[
\text{formal substrate}
\neq
\text{record ontology}
\neq
\text{record instance}
\neq
\text{presentation}
\]

This prevents, for example:

- identifying formal change directly with an Event;
- treating a Process as simply a mechanism;
- treating every Property as an intrinsic essence;
- treating a presentation as identical to the archived record.

## 6. Generativity and evolving distinctions

A future record model may need to represent not only changes of state but changes in what distinctions are available to an observer or system.

This suggests possible representations of:

- evolving equivalence or discrimination structures;
- emergent vocabulary;
- newly recognizable possibilities;
- transformed ontology or classification regimes.

This remains a research issue.

## 7. Why a standards program

The aim is not merely to write a single protocol.

A durable public standard requires:

- transparent development procedures;
- stable document classes;
- public review;
- recorded objections and dispositions;
- versioning;
- maintenance;
- conformance criteria;
- implementation guidance;
- technical interoperability.

Accordingly, the project is organized as a standards-development program rather than a single manuscript.
